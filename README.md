# Stream Panel

Личная серверная панель аналитики Twitch, DonationAlerts и YouTube для Руслана и Гульназ. Сбор работает на Linux VPS круглосуточно; браузер можно закрыть. Windows и Linux используются как клиенты браузера, установки приложения на компьютеры больше не нужны.

Один физический SQLite на сервере, отдельные таблицы и настройки интеграций для каждого профиля. Объединение людей и донатов выполняется только внутри своего профиля. YouTube хранится отдельно от Twitch/DA: совпадающий ник не связывает людей между платформами автоматически.

Панель открывается без логина. Переключатель профиля находится слева внизу. Данные профилей изолированы. SQLite WAL и IMMEDIATE-транзакции защищают параллельные записи, конфликты ревизий возвращают 409.

## Запуск для разработки

Node.js 24.19.0, pnpm 11.25.0, Linux:

```sh
pnpm install --frozen-lockfile
pnpm build
export STREAM_PANEL_DATA_DIR=/absolute/private/directory
export STREAM_PANEL_PUBLIC_ORIGIN=http://127.0.0.1:47831
pnpm start
```

Приложение слушает только 127.0.0.1; публичный доступ — через HTTPS-прокси. В production HTTP запрещён.

## Интеграции

- Twitch: свой public OAuth client, Device Code; Client Secret не нужен. Chatters — наблюдения участников чата, а не доказательство просмотра видео.
- DonationAlerts: OAuth-приложение, redirect из «Интеграций» на публичный HTTPS URL. Пока UTC offset не подтверждён, время доната остаётся неизвестным.
- YouTube: Google OAuth web client, YouTube Data API v3 + YouTube Analytics API, read-only scopes. Каждый входит в свой Google/Brand Account. Redirect из «Интеграций»; отчёты за 28 дней обновляются раз в 6 часов. Активные эфиры проверяются раз в 1–5 минут, до двух чатов на профиль; соблюдается pollingIntervalMillis. Локальный бюджет — 4000 единиц/профиль/день по Pacific Time, сохраняется в БД. Внешнее использование того же Google проекта может исчерпать квоту раньше.

Google OAuth в Testing может ограничивать срок refresh-токенов; настройка проекта и живой эфир проверяются перед production. Исторический чат до подключения и скрытые зрители не восстанавливаются. Смена канала показывает только его данные.

## Развёртывание и автоматические обновления

Инструкция: [docs/ops/server.md](docs/ops/server.md). `main` и `dev` сохраняются. Quality gate проверяет Linux, TypeScript/Svelte, unit/integration/e2e, покрытие ≥90% и откат деплоя. После зелёного CI текущий `main` выпускается как стабильный latest Linux `.deb`: [установка и перенос данных](docs/linux-release.md). Автодеплой VPS включается переменной `STREAM_PANEL_PRODUCTION_ENABLED=true` после проверки живого сервера. Старый desktop release v0.0.4 остаётся историческим.

Отдельные systemd-пользователи, каталоги, лимиты CPU/RAM, forced-command deploy key. При обновлении: maintenance → остановка службы → согласованный снимок → новая неизменяемая версия → healthcheck → включение сбора. Ошибка возвращает предыдущую версию, БД и настройки. Ротация сохраняет три версии и три снимка, затрагивая только каталоги Stream Panel.

Без покупки домена используется `stream-panel.<IP-с-дефисами>.sslip.io` и отдельный Caddy с автоматическим TLS. DNS/ACME и свободные 80/443 проверяются на выбранном сервере. Занятый порт означает остановку установки, существующий прокси не перезаписывается.

## Бэкапы

SQLite — единственный источник данных. Supabase используется только как закрытое Storage-хранилище шифрованных копий, синхронизация Postgres удалена. Копия содержит обе БД-профильные схемы, хэши аккаунтов и настройки подключений, шифруется AES-256-GCM после gzip. Ключ хранится отдельно; нужны отдельная сохранённая копия ключа и проверка восстановления.

Копии создаются каждые 12 часов и вручную (не чаще раза в 10 минут), остаются последние три. Без настроенного Supabase работают локальные шифрованные копии. Текущий предохранитель: SQLite ≤40 MiB, объект ≤48 MiB; превышение — явная ошибка, расширение до потоковых/частичных копий требуется при росте базы. Перед деплоем снимки без этого размера ограничения находятся только в закрытом серверном каталоге.

```sh
node scripts/restore-backup.mjs /private/backup.spbk /private/backup-key /new/empty/directory
```

Восстановление проверяет integrity/FK и отзывает старые сессии. Службу остановить до переключения каталога данных. Ключ и service-role key никогда не передаются браузеру.
