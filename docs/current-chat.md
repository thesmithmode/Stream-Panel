# Текущие зрители

Во вкладке стрима «Текущие зрители» используется общая таблица:

- Twitch: все участники последнего полного списка чата, включая молчащих.
  Время — объединение сохранённых наблюдаемых минут текущего логического стрима,
  сообщения и последнее сообщение — из его истории. Это не время просмотра видео.
- YouTube: авторы сообщений за последние 10 минут на продолжающейся YouTube-части
  стрима, с обычным красным оформлением и `@`. Число сообщений считается за весь
  текущий стрим; время присутствия неизвестно и показано прочерком. Истечение
  десяти минут не утверждает уход человека с трансляции.

Владелец (по постоянному ID и связанным аккаунтам) и боты скрыты по умолчанию.
Переключатель позволяет видеть их в фактическом списке, не меняя историю.
Каждый аккаунт площадки имеет отдельную строку со ссылкой на существующую карточку
человека: связанные Twitch/YouTube-аккаунты сохраняют разные основания присутствия.

`GET /api/v1/sessions/:id/current-chat?includeExcluded=0|1` читает сохранённые факты
выбранного профиля; никогда не вызывает провайдера. Модель чтения отделена от
сборщика, маршрута и отображения. Новая схема БД и новые зависимости не нужны.
Используется ограниченный кеш модели чтения (до 8 ключей): профильная модель,
стрим, фильтры, минута и версия фактов. Запись фактов, переименование/объединение
карточек, завершение эфира или изменение фильтра не оставляют старый результат
актуальным. HTTP ETag и профильные валидаторы клиента переиспользуются.

Таблица обновляется от существующего события `sp:data-refresh`, не чаще одного
чтения в минуту при автоматическом обновлении. Ручное обновление может перечитать
данные сразу. Второго таймера и запросов Twitch на каждого клиента нет. При
загрузке новых данных прежние строки остаются; ключи по площадке, аккаунту канала
и внешнему ID сохраняют DOM, сортировку и поиск. После ухода из вкладки запрос
отменяется; скрытая страница не запускает обновление таблицы.

Частичный/неуспешный опрос не заменяет последний полный список. Если последняя
попытка неуспешна или успешный список старше трёх минут, интерфейс явно помечает
его устаревшим. До первого снимка показывает ожидание. После завершения Twitch
старый состав Twitch не остаётся текущим даже при продолжающемся YouTube.
Из предыдущего Twitch-эфира список не переносится. При полностью завершённом
стриме предлагается история во вкладке «Участники».

Защита `ChatterHealth`, добавленная после инцидента с пустыми списками `rlod`,
продолжает работать в единственном сборщике. Переименование не участвует в
выборе текущего состава: используются числовые ID канала и участников.
