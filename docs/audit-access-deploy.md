## Приёмка живого запуска

1. Обычный HTTPS URL открывается на ПК и телефоне без туннеля; сертификат доверенный, anonymous API → 401, неправильный пароль → 401, чужой Origin/неверный CSRF → отказ.
2. Две независимые сессии входят своими аккаунтами, обе видят оба профиля; выбор профиля и logout одной сессии не меняют другую. Подключение OAuth завершается в начальном профиле даже после переключения другого браузера.
3. Импортированная история пользователя есть на VPS; новые события собираются после закрытия браузера, restart службы и reboot. `healthz` проверяет только SQLite/релиз (`hosted.ts:85`), поэтому живой сбор требует отдельных реальных событий интеграций, а не одного green healthcheck.
4. Создаётся локальная encrypted copy и remote private copy Stream Panel; восстановление в отдельный каталог сохраняет историю и отзывает старые сессии (`backup.ts:102`). Проверить искусственный неудачный healthcheck/rollback и последние три копии.
5. В истории Actions видны bootstrap, перенос, configure и deploy из main; ручных изменений VPS нет, имеющиеся контейнеры/службы продолжают работать.

Почему такое решение, даже если кажется странным:
- Общая статистика двух владельцев разрешена последним уточнением пользователя. Разделение таблиц/интеграций сохраняется для корректного учёта, а запрет cross-profile чтения больше не является критерием доступа.
- Бесплатное DNS-имя вида `stream-panel.23-95-166-119.sslip.io` предусмотрено bootstrap (`ops/bootstrap.sh:37`); это вариант без покупки домена, но DNS и ACME ещё надо проверить живым workflow. Отчёт не утверждает, что TLS уже выдан.
- На занятом 80/443 дополнительный Caddy не решает доступность: входящий трафик уже принадлежит действующему прокси. Нужна минимальная отдельная маршрутизация через него после инвентаризации, без удаления или переписывания его существующих конфигураций.
