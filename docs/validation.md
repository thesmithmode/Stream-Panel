## Синтетическая нагрузка

Отчёт: [benchmark-results.json](benchmark-results.json).10 000 событий и480 полных опросов по1000 identity, WAL/FULL. Измеряется настоящий `StreamStore.recordPoll` и сетка `StreamStore.grid` на480 минут для одного Person. Это storage smoke в одном тестовом процессе; event loop measurement относится к нему, а не к daemon HTTP.

Проверка не является восьмичасовым сбором, Windows benchmark, сетевым тестом или годовым набором данных. Она не доказывает UI p95<500ms и не моделирует точные приходы/уходы зрителей. Временная БД удаляется после измерения.

До оптимизации настоящий путь сетки занимал около202.6ms, запись poll p95 —102.8ms. Повтор после переиспользования statements и одного индексированного запроса на весь диапазон: **сетка1.90ms, poll p95 15.94ms**, все480 наблюдаемых минут сохранены. БД93.7MB, RSS306.6MB в синтетическом процессе. Это локальные измерения, не гарантия на любом ПК.

CI [37535212725](https://github.com/thesmithmode/Stream-Panel/actions/runs/37535212725) для последнего commit с кодом `89ec4b1` прошёл на **Ubuntu и Windows**: установка и `pnpm check`. Обе задачи завершились success. Следующий коммит обновляет только документацию результата.
