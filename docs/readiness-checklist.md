# Готовность серверной Stream Panel 0.1

Текущая архитектура: постоянно работающий Linux-сервер, HTTPS-панель в браузере, два аккаунта с изолированными профилями и одна SQLite. Зашифрованные локальные резервные копии обязательны; загрузка в Supabase Storage включается отдельно. Десктопный v0.0.4 — исторический выпуск. Windows-установщики, синхронизация двух БД и остановка чужого desktop daemon больше не входят в план.

## Выпуск и проверка живой инфраструктуры

Рабочая серверная версия уже развёрнута. Успешный предшествующий выпуск: `f35c062188ba1a295bc42e607cc861fd59255ea4`, Quality gate `38091281757`, Deploy server `38091415651`. Это исторические свидетельства; каждый новый выпуск проверяется по собственному SHA.

Изменения ведутся в `dev`. Пользователь разрешил перенос проверенных исправлений в `main` после зелёного CI; workflow автоматически устанавливает неизменяемый server bundle для точного SHA. Сборщик и UI работают в разных процессах, но используют общий цикл остановки сервиса. Обновление создаёт короткий перерыв наблюдений; чатовые события во время остановки нельзя гарантированно восстановить задним числом.

В текущем обновлении deployment дополнительно скачивает свежую зашифрованную копию из настроенного Supabase, сравнивает хеш с локальной копией, восстанавливает её во временный каталог и проверяет SQLite integrity, foreign keys, версии схем обоих профилей и наличие всех таблиц. Действующая БД при этой проверке не заменяется. Результат сохраняется в Actions без ключей и содержимого сообщений.

Обязательные эксплуатационные проверки: авторизация каждого нужного аккаунта и scopes; длительный эфир с обрывами сети; наблюдение за квотами, свободным местом и статусом бэкапов. Подробности полноты сбора и ограничений: [collection-review.md](collection-review.md).

Бэкап выполняется при запуске и каждые 15 минут. Локально остаются до семи копий не старше двух суток; в облаке — семь последних подтверждённых копий. Полный зашифрованный архив ограничен 2 GiB. Большие облачные копии загружаются частями по 16 MiB; манифест публикуется после проверки всех частей. Ограничение одного объекта 48 MiB больше не блокирует растущую БД.

Политика качества: минимум 95% строк, ветвлений и функций в суммарном backend + браузерном отчёте, плюс отдельная проверка строк каждого учитываемого файла. Порог не снижать и исключения не добавлять. Наличие кода или старого зелёного запуска не подтверждает готовность нового SHA.

Живая проверка 2026-10-11 обнаружила отсутствие облачной конфигурации на сервере и пустой Supabase bucket. До настройки ключа наличие актуального облачного бэкапа не подтверждается; deployment audit остаётся красным. Подробные результаты: [collection-review.md](collection-review.md).
