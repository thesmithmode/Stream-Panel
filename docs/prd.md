# PRD: Stream Panel

| Поле | Значение |
|------|----------|
| Продукт | Stream Panel |
| Репо | https://github.com/thesmithmode/Stream-Panel |
| Ветка разработки | `dev` (`main` — только релизы) |
| Стадия | Продумывание / документация |
| Референс | [Stream Tools by b1trat3](https://b1trat3.ru/products/stream-tools) — аналитика и модель событий, **не** клон виджетов |

## 1. Проблема

Стримеру нужно видеть аудиторию как людей: один человек может донатить в DonationAlerts под одним ником и писать в Twitch-чат под другим. Разрозненные ленты событий не дают ответа «кто реально ценен», «кто пришёл на сколько минут» и «что происходило в конкретную минуту эфира».

## 2. Цель продукта

Локальный долгоживущий сервис аналитики стрима с дашбордом:

1. Склеивать события разных источников в сущность **Person**.
2. Хранить историю локально (с опциональным бесплатным remote backup).
3. Давать presence и активность с минутной разбивкой в рамках того, что реально позволяет Twitch + DA (+ позже Streamer.bot).

## 3. Для кого

Владелец канала (thesmithmode и аналогичный сетап): стрим с Windows или Linux, Twitch + DonationAlerts, позже Streamer.bot.

## 4. Что берём / не берём у Stream Tools

| У Stream Tools | В Stream Panel |
|----------------|----------------|
| Пайплайн событий с площадок | Да (идея ingest) |
| Локальная аналитическая БД | Да |
| Сущность человека / склейка ников | Да (явная модель Person + manual merge) |
| OBS HTML-виджеты, розыгрыши, аукцион, эмулятор ввода | Нет |
| Windows-only EXE как единственный рантайм | Нет — Windows **и** Linux |

Публичное описание аналитических экранов Stream Tools скудное; модель «человек / склейка» из публичных источников **неизвестна** (см. [research-notes.md](./research-notes.md)) — проектируем сами. UX-экраны — по метрикам из требований (топы, таймлайн, карточка человека, минутная сетка presence).

## 5. Пользовательские сценарии (v1)

1. **Во время стрима:** сервис запущен; события Twitch/DA пишутся в БД; дашборд показывает текущую сессию.
2. **После стрима:** открыть прошлую сессию; топ донатеров и чаттеров; карточка человека с минутами просмотра и сообщениями.
3. **Склейка:** система предложила матч «донат Вася ≈ чат Вася»; пользователь подтвердил. Или вручную склеил «Петя» + «Петя123».
4. **Разбор минуты:** «кто был в chatters / писал в 12:03 DD.MM».
5. **Бэкап:** опционально БД уезжает на бесплатный remote (см. tech-spec), восстановление на новой машине.

## 6. MVP (1–2 недели после старта кода)

**In scope**

- Демон на Win/Linux + локальный web-UI.
- Ingest: Twitch (EventSub чат/сабы/биты/фоллоу/рейд/stream online-offline + poll Get Chatters) и DonationAlerts (донаты).
- SQLite: sessions, events, persons, person_identities, presence_samples.
- Автоматч по нормализованному display/login + UI ручной merge/unmerge.
- Экраны: текущая/последняя сессия, топы, таймлайн, карточка Person, минутная сетка presence (по сэмплам).
- Конфиг OAuth/токенов вне git; README по запуску.
- Опциональный Litestream → Cloudflare R2 (или B2): checklist в tech-spec / research-notes.

**Out of scope MVP**

- Streamer.bot adapter (только интерфейс/заглушка в архитектуре).
- YouTube / Kick / VK / DonatePay.
- OBS-оверлеи.
- Идеальный учёт анонимов без chatters.
- Облачный multi-user SaaS.

## 7. Критерии успеха MVP

- На живом тестовом стриме видны донаты DA и сообщения Twitch, привязанные к Person.
- Для модераторского токена канала восстановлен таймлайн «был в chatters» с шагом ≈1 мин.
- Ручная склейка двух identity в одного Person отражается во всех топах.
- Репо остаётся без секретов; работа только в `dev`.

## 8. Риски

| Риск | Митигация |
|------|-----------|
| Twitch не даёт точный join/leave на каждую секунду | Poll Get Chatters + честный UX «по сэмплам»; см. tech-spec |
| Chatters ≠ все viewers (анонимы, embed без чата; боты в чате) | Документировать; фильтр известных ботов; не обещать «как у Twitch Dashboard» |
| Get Chatters требует moderator scope | Онбординг: стример авторизуется как broadcaster/mod |
| Rate limit / cache API | Интервал poll ≥ 60 с |
| Публичный репо | Секреты только локально; в docs — пересказ, не личные данные |
