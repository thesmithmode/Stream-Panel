# PRD — Stream Panel v1

Статус 2026-10-06: работающая ранняя программа в `codex-init`; локальный daemon/UI проверен, сетевые адаптеры написаны, живой вход ещё не проверен. Этот PRD описывает целевую v1, а не объявляет все требования реализованными. Текущая готовность — в [validation.md](validation.md), backlog — в [implementation-plan.md](implementation-plan.md).

## 1. Задача и границы

Дать владельцу одного Twitch-канала локальную историю активности и донатов, связать известные identity в управляемые Person, показать наблюдения по минутам и полноту данных. Twitch + DonationAlerts обязательны; приложение работает на Windows и Linux без Streamer.bot.

Публичная страница Stream Tools подтверждает инструменты эфира и интеграции, но **не подтверждает** локальную аналитическую БД, Person или склейку донат↔чат. Эти функции проектируем по требованиям владельца; не обещаем совместимость с файлами, аккаунтами или внутренней схемой референса.

## 2. Контракт честности

| Экран / показатель                       | Что означает                                                           | Что запрещено утверждать                             |
| ---------------------------------------- | ---------------------------------------------------------------------- | ---------------------------------------------------- |
| «Участники чата, последний полный опрос» | Users из завершённого Get Chatters; рядом время и возраст ответа       | «Все смотрящие сейчас»                               |
| «Минуты с наблюдением в чате»            | Количество уникальных UTC-минут с успешным полным опросом и membership | «Минуты просмотра»                                   |
| «Не наблюдался»                          | В полном опросе пользователя не было                                   | «Точно не смотрел видео»                             |
| «Нет данных»                             | Нет полного опроса в минуте, ошибка, приложение выключено              | Нулевое присутствие / уход                           |
| «Первое / последнее наблюдение»          | Первый / последний успешный sample                                     | Точный приход / уход                                 |
| «Сообщения»                              | Дедуплицированные сообщения в выбранном диапазоне и канале             | Полная история при потерях соединения                |
| «Донаты»                                 | Уникальные DA alert ID, суммы отдельно по валютам                      | Сумма разных валют без курса; чистый доход / выплаты |
| «Человек»                                | Управляемая аналитическая группа аккаунтов / событий                   | Доказанная физическая личность по одинаковому имени  |

Интерполяции в v1 нет. Полный пагинированный опрос сам не атомарен и может быть задержан Twitch. Частичные положительные ответы доступны в диагностике, в основной сетке считаются неизвестностью. Сообщение — самостоятельный сигнал активности, оно не заменяет membership Chatters.

## 3. Функциональные требования и приёмка

| ID   | Поведение                           | Проверяемое условие                                                                                                                             |
| ---- | ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| FR01 | Подключить собственный Twitch-канал | Проверены client/user IDs, scopes; UI показывает работающие и недоступные возможности отдельно                                                  |
| FR02 | Подключить DA                       | Локальная конфигурация приложения; WS-событие и REST одного доната не удваивают сумму                                                           |
| FR03 | История эфиров                      | Запуск посреди эфира находит stream ID через Helix; рестарт сохраняет ту же сессию                                                              |
| FR04 | Сбор чата и событий                 | Каждый факт имеет source, recipient, provider ID, timestamp basis; разрыв отображается                                                          |
| FR05 | Presence                            | Все страницы опроса; 401/429/ошибка страницы не превращается в пустой полный список                                                             |
| FR06 | Person / Identity                   | Twitch rename сохраняет ID; донатное имя не становится уникальным аккаунтом                                                                     |
| FR07 | Автоматч и предложения              | Unique nick Twitch↔DA (`matchKey`) → auto-link в один Person; неоднозначные имена — только кандидаты; разные ники — ручной merge (FR08)           |
| FR08 | Ручные операции                     | Merge пересчитывает атрибуцию; undo возвращает состав, split выделяет identities; ревизии проверяются, конфликт не применяет частичную операцию |
| FR09 | Донатная история                    | Импорт возобновляется; неизвестный timezone не присваивается минуте эфира автоматически                                                         |
| FR10 | Аналитические экраны                | Одинаковые фильтры интервала, валюты, сессии и excluded identities дают одинаковые суммы во всех экранах                                        |
| FR11 | Сохранность                         | Ошибка диска видна; данные подтверждаются сохранёнными только после commit                                                                      |
| FR12 | Backup / restore                    | Snapshot живой WAL-БД восстанавливается; база проверяется и не затирает действующий файл                                                        |
| FR13 | Локальная защита                    | Другой сайт не читает API и не вызывает merge; секретов нет в API/экспортах/репо                                                                |
| FR14 | Работа в фоне                       | Закрытие вкладки не останавливает сбор; SIGTERM завершает запись; после sleep виден пробел                                                      |

## 4. Пользовательские сценарии

1. Первый запуск: выбрать папку данных, проверить соединения, авторизоваться в браузере; диагностическая страница сообщает недостающие права. Не требовать OBS/Streamer.bot.
2. Во время эфира: видеть текущую сессию, свежесть опроса, сообщения, донаты и состояния источников. Частично доступные сервисы не мешают другим.
3. После эфира: сравнить сессии, открыть топы и таймлайн, перейти в Person; неполные интервалы подписаны.
4. Найти человека: по Twitch ID, текущему/историческому нику или имени доната; разные лица с одинаковым именем остаются различимыми.
5. Склеить разных ников: предварительный просмотр, затем merge «донатер X = зритель Y» — прошлые и будущие донаты/активность в одном Person. Одинаковый nick уже склеен автоматом (FR07). Отклонённая пара не предлагается снова без нового правила (durable reject — P1).
6. Исправить ошибку: undo последнего merge либо split выбранных identity / отдельных донатов; показывать воздействие на всю историю. Ничего не удалять из fact log.
7. Разобрать «12:03 определённого дня»: UTC-минута и локальная подпись, наблюдения, сообщения и донаты с известным временем; неизвестные времена отдельной лентой.
8. Сохранить / восстановить: snapshot, статус последнего удачного backup; восстановление в отдельный файл, проверка схемы и integrity, затем ручной выбор восстановленной базы.

## 6. Формулы

- `messageCount`: число уникальных `chat.message` в выбранном канале и `[from, to)`. Shared Chat внешнего исходного канала исключён по умолчанию.
- `messagesPerMinuteOfSession`: messageCount / длительность выбранной сессии в минутах; при неизвестной границе — null, не делить на estimated presence.
- `observedChatMinutes`: distinct floor(sample.completedAt / 60000) по полным poll, где присутствует хотя бы одна identity выбранного Person. После merge не суммировать пересекающиеся минуты дважды.
- `coverage`: число минут с полным poll / число минут записи в диапазоне; показывать независимо от identity. 60s poll — продуктовый default, не гарантия freshness сервера.
- `donationTotal`: сумма exact minor units одной валюты; attribution по текущей подтверждённой membership. Неразобранные донаты выделены отдельно, глобальная сумма их учитывает.
- Сессия: интервал `[startedAt, endedAt)`, unknown timestamps не входят в интервал по времени получения. Онлайн-донаты вне эфира сохраняются.
- В топах нет универсального «ценность человека», сложного score или конвертации валют: такие метрики владелец не задавал.

## 7. Нефункциональные требования

Цели, требующие измерения на целевом ПК: 8-часовая запись, 1 000 chatters / 60s, 50 событий/с со всплеском 200/с 10s, UI ответ p95 <500ms на годовой синтетической истории, отсутствие unbounded queues. Это budget проверки, не уже подтверждённая производительность.

Синтетический smoke-тест storage проведён отдельно. Native Windows install/test, mint install, OAuth/WS и длительная работа — отдельные release gates. Срок «MVP 1–2 недели» удалён: до закрытия gates он не обоснован.

Требование качества владельца от2026-10-06: TDD, unit/integration/E2E по риску функции, автоматические проверки всех веток и PR, покрытие собственного runtime ≥90% строк/ветвлений/функций суммарно и ≥90% строк каждого файла. Условия, исключения и команды — в [стратегии тестирования](testing-strategy.md).

## 8. Вне v1

Виджеты OBS и интерактив Stream Tools, другие площадки, публичный SaaS, автоматический cross-platform матч по имени без согласия, canonical watch time, восстановление утраченного Twitch-чата, полноценный multi-writer sync, упаковка в один EXE и обязательная облачная инфраструктура.
